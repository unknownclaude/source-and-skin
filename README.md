# Source and Skin

A storefront for African net sponges and Salvadora persica miswak. Next.js 14
(App Router), TypeScript, Tailwind, Framer Motion. Content is static and typed —
there is no CMS or backend yet, and the data is shaped so that adding one is an
adapter, not a rewrite.

```bash
npm install
npm run dev      # http://localhost:3000
```

| Script                | What it does                                     |
| --------------------- | ------------------------------------------------ |
| `npm run dev`         | Dev server                                       |
| `npm run build`       | Production build (all routes prerender)          |
| `npm run start`       | Serve the production build                       |
| `npm run lint`        | ESLint (`next/core-web-vitals`)                  |
| `npm run typecheck`   | `tsc --noEmit`                                   |

## Where the content lives

Two files hold everything you are likely to want to change.

### `data/site.ts` — brand level

Name, tagline, description, contact email, social handles, and the nav
structure. Nothing hardcodes the brand name; every component reads it from here,
so a rename is a one-line change.

`heroVideo` also lives here — see [Hero video](#hero-video) below.

### `data/products.ts` — the catalogue

Five seeded products. The `Product` type is the app-facing contract:

```ts
type Product = {
  slug: string;
  name: string;
  category: "sponge" | "miswak" | "bundle";
  price: number;            // major units (USD), formatted by lib/format.ts
  tagline: string;
  description: string;
  howToUse: string;
  materials: string;
  accentColor: string;      // hex — the spotlight/card background
  images: { main: string; alt: string; gallery: string[] };
  shipping?: string;        // falls back to defaultShippingCopy
  featured?: boolean;       // appears in the homepage featured row + spotlights
};
```

Adding a product means adding an object to the `products` array. The shop grid,
the filter bar, the sitemap, `generateStaticParams` for the product pages, the
footer's shop column and the related-products row all read from it.

**`accentColor`** drives the full-bleed spotlight blocks. Pick from the palette
in `tailwind.config.ts` (terracotta `#C57A54`, olive `#6B7259`, clay `#8C4A3B`)
and try not to give two adjacent shop-grid cards the same one. Text colour on
the accent is computed by `readableTextOn()` in `lib/format.ts` using WCAG
relative luminance, so a new accent will not silently produce unreadable type.

## Replacing the placeholder imagery

Every file in `/public/images` is placeholder art — flat vector compositions
generated by `scripts/generate-placeholders.mjs` and rasterised to JPG. They are
stand-ins for photography, not a design element to preserve.

**To swap in real photos:** drop `.jpg` files into `/public/images` with the same
filenames and delete `scripts/generate-placeholders.mjs`. Or use your own names
and update the paths in `data/products.ts`.

Aspect ratios the layout expects:

| Use                            | Ratio  | Files                                     |
| ------------------------------ | ------ | ----------------------------------------- |
| Product shots (cards, PDP)     | 4:5    | `placeholder-<product>.jpg` and `-alt`    |
| Wide editorial bands, hero     | ~16:9  | `placeholder-hero-poster`, `-editorial-*` |
| Lifestyle / texture            | 4:3–4:5| `placeholder-lifestyle-*`, `-texture-*`   |

Two things the placeholder art had to get right, worth preserving in the real
photography:

- **The subject needs tonal separation from its ground.** Product shots sit on
  their own `accentColor`, and a low-contrast subject on a matching background
  disappears entirely in the spotlight blocks.
- **Keep the left ~55% of the wide bands quiet.** The hero and the "daily
  ritual" band overlay left-aligned headlines; a busy subject there fights the
  type.

All imagery goes through `next/image` with explicit `alt` text. Decorative
images pass `alt=""` with `aria-hidden` — keep that distinction when swapping.

### Grading real photography into the palette

Net sponges photograph vivid — they genuinely are bright, and they are usually
shot outdoors against whatever happened to be behind them. Dropped in raw, that
fights the cream/charcoal/earth system and reads as a snapshot rather than a
brand shot.

`scripts/process-photo.mjs` crops, grades and veils a photo into the palette:

```bash
node scripts/process-photo.mjs ~/photo.jpg --out net-sponge-regular \
  --preset product --crop 0.05,0.18,0.42,0.42 --sat 0.72 --veil 0.10 --veilcolor clay
```

| Flag          | Does                                                          |
| ------------- | ------------------------------------------------------------- |
| `--preset`    | `product` (4:5), `wide` (16:9), `band`, `square`               |
| `--crop`      | `x,y,w,h` as fractions of 0–1 — cut away fences, posts, hands  |
| `--sat`       | saturation multiplier; 0.55–0.75 is the useful range           |
| `--warm`      | strength of the warm cast (default 0.5)                        |
| `--veil`      | opacity of the colour wash — the step that unifies             |
| `--veilcolor` | `cream` (default), or an accent name for spotlight shots       |

Two rules matter more than the flags:

- **Crop the background out.** A garden fence, a post, or a string of lights
  cannot be graded into luxury. Crop to the fibre.
- **One colour per frame.** A rail of twenty multicoloured nets is a market
  stall; a single net on a plain ground is a product. Keep that one colour
  vivid and let the accent ground frame it — that reads as intentional. Save
  the heavy desaturation for the wide editorial bands, where the photo is
  texture behind type rather than the subject itself.

### Hero video

The hero renders its poster image alone until you give it a video. Drop a file
at `/public/videos/hero.mp4` and set `heroVideo` in `data/site.ts`:

```ts
heroVideo: "/videos/hero.mp4",
```

Encoding brief is in `public/videos/README.md`. The video is progressive
enhancement — a missing file, blocked autoplay, or `prefers-reduced-motion`
all fall back to the poster, which is why the poster should be a frame you are
happy to ship on its own.

## Wiring up real checkout

The cart is real but local: `components/CartProvider.tsx` holds line items in a
reducer and mirrors them to `localStorage`. Nothing leaves the browser, and the
checkout button in the drawer is deliberately inert and labelled as such.

Keep `CartProvider`'s context as the UI contract — `lines`, `count`, `subtotal`,
`add`, `setQuantity`, `remove` — and replace the internals.

### Option A — Shopify (Storefront API)

Best fit if you want Shopify to own inventory, tax and fulfilment.

1. `npm i @shopify/storefront-api-client`. Add `SHOPIFY_STORE_DOMAIN` and
   `SHOPIFY_STOREFRONT_ACCESS_TOKEN` to `.env.local`.
2. Write `lib/shopify.ts` exporting `getProducts(): Promise<Product[]>` that
   queries `products(first: 50)` and maps the response onto the existing
   `Product` type — Shopify's `handle` is our `slug`, `priceRange.minVariantPrice`
   is our `price`, media edges are our `images`, and the accordion copy
   (`howToUse`, `materials`) maps onto metafields.
3. Make the pages that import `data/products.ts` `async` and await the adapter
   instead. Components take products as props already, so they do not change.
4. Store the Shopify variant ID alongside each line in `CartProvider`, swap the
   reducer's `add`/`setQuantity`/`remove` for `cartLinesAdd` / `cartLinesUpdate`
   / `cartLinesRemove` mutations, and point the drawer's checkout button at the
   returned `cart.checkoutUrl`.

The simplest possible version — a Shopify **Buy Button** embed on each PDP —
skips all of that, at the cost of the site's own cart UI.

### Option B — Stripe Checkout

Better if the catalogue stays small and you do not want a second CMS.

1. `npm i stripe`. Add `STRIPE_SECRET_KEY` to `.env.local`.
2. Create products/prices in Stripe and record each `price_...` id on the
   product (a `stripePriceId` field on `Product`).
3. Add `app/api/checkout/route.ts` that reads the cart lines from the request
   body, re-derives quantities and price ids **server-side from your own
   catalogue** (never trust prices sent by the client), creates a Checkout
   Session, and returns its URL.
4. Point the drawer's checkout button at that route and redirect to the session
   URL.

Either way, remove the `disabled` attribute and the "coming soon" label in
`components/CartDrawer.tsx`.

### The two forms

`NewsletterForm` and `ContactForm` both validate properly and then resolve
against a stub. Each has one clearly marked function to replace:

- `fakeSubscribe()` in `components/NewsletterForm.tsx` → POST to Klaviyo,
  Mailchimp, ConvertKit, or your own `/api/subscribe`.
- The `setTimeout` in `ContactForm`'s `onSubmit` → POST to `/api/contact`,
  Formspree, or Resend.

The pending / success / error states around them already work.

## Structure

```
app/
  layout.tsx            fonts, metadata, cart provider, nav + footer
  page.tsx              home
  shop/                 grid with filter + sort
  products/[slug]/      PDP — prerendered per product, Product JSON-LD
  about/ sourcing/ contact/ faq/
  sitemap.ts robots.ts icon.svg not-found.tsx
components/
  Navbar Hero ProductCard ProductSpotlight EditorialSection
  NewsletterForm Footer Accordion ProductGallery AddToCartForm
  ShopGrid ContactForm CartProvider CartDrawer Reveal SectionHeading
data/       products.ts, site.ts
lib/        format.ts — price formatting, cn(), contrast helper
scripts/    generate-placeholders.mjs — delete once real photos land
```

### Conventions worth keeping

- **Server components by default.** `"use client"` appears only where there is
  state, motion, or a browser API. The PDP, shop page and all the editorial
  pages are server-rendered; only the interactive islands ship JS.
- **Motion degrades.** `Reveal` and `Hero` both check `useReducedMotion()` and
  render the end state immediately; `globals.css` also cuts transition durations
  under `prefers-reduced-motion`. Content is never hidden behind an animation
  that might not run.
- **Accessibility.** Semantic landmarks, one `h1` per page, a skip link,
  keyboard-operable accordions (`aria-expanded` / `aria-controls`), a focus trap
  and Escape handler in the cart drawer, and visible focus rings.
- **SEO.** Per-page `title`/`description`, canonical URLs, Open Graph and
  Twitter cards from `data/site.ts`, `Product` JSON-LD on the PDP, `FAQPage`
  JSON-LD on the FAQ, plus generated `sitemap.xml` and `robots.txt`. Set the
  real domain in `site.domain` before launch — `metadataBase` reads from it.
